为什么是本地套件

网站只做静态展示

Cloudflare 免费静态站不执行 Python/R、不运行论文代码，也不托管 MCP。所有生成都发生在你的电脑上。

认证只看包，不看来源

手动、Paper2Agent 或其他方式生成的 MCP 都可以提交；我们统一检测后给出 已认证 / 未认证。

认证不是结果认证

MCP 通过检测，不代表某个数据集上的结果是 正式复现；结果等级仍单独记录。

未认证也能被看到

未认证条目可展示、可自行使用，但风险自担；通过检测后升级为已认证。

五步生成

  1. 下载并解压套件

    把顶层的 paper2agent/ 目录复制到你的编码 Agent skills 目录，重启 Agent。

  2. 准备论文和代码

    准备论文 PDF/链接、代码仓库或本地路径、输出目录。受限数据不要交给 Agent，也不要在网页上传。

  3. 复制提示词运行

    把下面的提示词填入 Agent，替换占位符。Agent 会生成 Paper2Skill、MCP 包和验证记录。

    Read the paper2agent skill and use it to agentify this paper and its code.

Paper and associated files:
- <PAPER_PDF_OR_URL_OR_LOCAL_PATH>

Code repository (if available):
- <GITHUB_URL_OR_LOCAL_PATH>

Output directory:
- <PROJECT_DIR>

Task focus (optional):
- <METHOD / TUTORIAL / SOURCE_URL>

Requirements:
1. Follow the paper2agent workflow: paper understanding, code audit,
   Skill/MCP generation, runtime verification, and final delivery.
2. Keep the paper, code, and generated artifacts traceable.
3. Do not download or upload restricted data.
4. Do not execute untrusted code outside the isolated project environment.
5. Record runtime versions, commands, test data, and known limitations.
6. The MCP must not receive held-out truth and must not compute benchmark metrics.
7. Produce a package that can be submitted to GSGP-Bench for MCP certification.
  4. 本地检查并运行

    确认 Skill/MCP 的输入、输出、依赖、许可证和限制；用公开或合成数据跑一次，保存日志和产物。

  5. 提交认证

    通过 GitHub Issue 提交 MCP。中央团队检测契约、运行、truth 隔离和安全边界；通过后显示已认证。

认证路径

未认证

包已提交但未通过/未完成中央检测。网站可展示，用户可自行使用，风险自担。

已认证

中央团队实践验证过固定版本：契约、启动、参考数据、输出、direct 对照、truth 隔离和安全边界。

注意：认证的是 MCP 包，不是论文结果，也不是在线服务。结果等级仍单独使用 演示 / 流程测试 / 探索 / 正式复现 / 论文值；GBLUP 当前是探索，IFAM 当前是流程测试。
