提交 MCP

我们用 已认证 / 未认证 两个状态，不托管在线 MCP。已认证表示 GSGP-BENCH 团队实践验证过这个版本的 MCP 包；它不代表论文结果认证，也不代表网站在线执行。

还没有生成包？先下载本地 Paper2Agent 套件 →

流程

  1. 用本地 Paper2Agent 套件生成包，准备 Skill、MCP 服务、工具契约、运行说明和公开/合成测试数据。
  2. 在仓库的 Issues → New issue → MCP submission 提交表单（模板：.github/ISSUE_TEMPLATE/mcp-submission.yml）。
  3. GSGP-BENCH 团队统一运行参考数据、检查输入输出、真实值隔离、安全边界和来源记录。
  4. 通过 → 标记 已认证；未通过或尚未审核 → 保持 未认证，仍可被查看和使用，但风险自担。

提交需要包含

  • 论文标题、DOI/链接；
  • 官方代码仓库、commit、许可证；
  • Paper2Agent Skill 和 MCP 包/入口；
  • MCP transport、运行方式、依赖；
  • 一条可重复执行的测试命令和参考数据；
  • 期望输出与已知限制；
  • 明确声明：MCP 不接收留出的真实值，不计算评测指标。

认证边界

已认证的是 这个 MCP 包和固定版本，不是任何一次运行结果，也不是在线服务。用户仍然需要自己安装、运行并核对结果。结果等级仍单独记录为 演示 / 复现 / 探索 / 流程测试 / 论文值 / 未运行。

未认证条目允许公开查看和自行使用，但网站不会为它背书；使用前请检查来源、许可证和限制。

两阶段生命周期：先预期，后校验

为了让评测页在结果跑出来之前就能看到“方法 × 数据集”的相对位置，我们把它拆成两个阶段。第一阶段的数值是 运行前预期，永远带 tool_status=unverified 和 validation_status=pending_validation 标签，不能作为科学结果引用。

  1. 阶段 1 · 运行前预期（未认证）。评审代理只读取提交的 PR（标题、正文、diff）和论文/文档依据，生成 site/data/prospective/submissions.json：每条记录含 expected（0–100 适配度）、confidence、预期指标区间，以及可核验的 reasoning（证据 / 风险 / 验证计划）。生成器 scripts/prospective-from-pr.mjs 会拒绝任何试图写入真实指标或 certified 的输出，CI 也会二次拦截。此时页面上“MCP 工具状态”显示为 未认证。
  2. 阶段 2 · 人工校验后的真实指标（认证）。GSGP-BENCH 团队用独立 runner 在固定数据、划分和环境下真实运行，把 metrics 写入 benchmark/runs/<run-id>/result.json 与 site/data/results/*.json。只有通过校验后，对应记录才从“主观估计”切换为真实指标，并把 MCP 工具状态更新为 已认证。

预期记录只用于安排验证优先级，不参与主榜、认证、复现结论或论文级比较。任何把预期数值当复现结果的做法都视为违反证据边界。

# 阶段 1：从 PR 生成运行前预期（需 OPENAI_API_KEY，可选 GITHUB_TOKEN / OPENAI_BASE_URL / OPENAI_MODEL）
npm run prospective:from-pr -- --pr https://github.com/OWNER/REPO/pull/123 \
  --out site/data/prospective/submissions.json

# 本地离线自检：用内置示例，不联网
node scripts/prospective-from-pr.mjs --mock --input pr.json --out /tmp/prospective.json

  1. 准备上游 IFAM 归档，导出 500×5k 本地子集；原始数据不提交。

  --run-id gblup-sim500-v1
