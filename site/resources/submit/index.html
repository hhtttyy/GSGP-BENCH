提交 MCP

我们用 已认证 / 未认证 两个状态，不托管在线 MCP。已认证表示中央团队实践验证过这个版本的 MCP 包；它不代表论文结果认证，也不代表网站在线执行。

还没有生成包？先下载本地 Paper2Agent 套件 →

流程

  1. 用本地 Paper2Agent 套件生成包，准备 Skill、MCP 服务、工具契约、运行说明和公开/合成测试数据。
  2. 在仓库的 Issues → New issue → MCP submission 提交表单（模板：.github/ISSUE_TEMPLATE/mcp-submission.yml）。
  3. 中央团队统一运行参考数据、检查输入输出、truth 隔离、安全边界和 provenance。
  4. 通过 → 标记 已认证；未通过或尚未审核 → 保持 未认证，仍可被查看和使用，但风险自担。

提交需要包含

  • 论文标题、DOI/链接；
  • 官方代码仓库、commit、许可证；
  • Paper2Agent Skill 和 MCP 包/入口；
  • MCP transport、运行方式、依赖；
  • 一条可复现测试命令和参考数据；
  • 期望输出与已知限制；
  • 明确声明：MCP 不接收 held-out truth，不计算 benchmark 指标。

认证边界

已认证的是 这个 MCP 包和固定版本，不是任何一次运行结果，也不是在线服务。用户仍然需要自己安装、运行并核对结果。结果等级仍单独记录为 演示 / 流程测试 / 探索 / 正式复现 / 论文值。

未认证条目允许公开查看和自行使用，但网站不会为它背书；使用前请检查来源、许可证和限制。
