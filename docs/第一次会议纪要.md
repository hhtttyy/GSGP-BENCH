根据会议纪要，团队最终确定的完整方案如下：

 

## **一、方案背景与核心目标** 

当前 **GS****（Genomic Selection）****GP****（Genomic prediction）****领域缺乏统一的算法评测基准**，不同论文提出的算法往往没有在公平、透明的数据集上进行对比，导致难以判断方法的优劣。

本方案的核心目标是：**利用 AI 技术复现和对比 GSGP 领域的论文，建立一个公正的算法评测基准**，让不同论文提出的算法可以在统一的数据集上进行公平比较。

 

## **二、技术路径** 

​                ● **基础框架**：采用 **“paper-to-agent”**  项目（该论文约 2025 年 3-4 月投稿，10 月 13 日接收，首次提出将论文复现并转化为多智能体的自动化范式，https://github.com/jmiao24/Paper2Agent）。 

​                ● **核心机制**：将 GSGP 领域的研究论文转化为可调用的 **MCP（最小可编程单元 / MCP Server）**。每篇论文的方法被“代码化、工程化”，变成可被任意 Vibe coding 框架调用的智能体。 

​                ● **评测逻辑**： 

​                ● 若论文方法能成功转为 MCP，则在**统一的数据集**上直接运行 Benchmark； 

​                ● 若无法转为 MCP，则按论文描述的训练集、验证集划分进行**简单打分**； 

​                ● 智能体自动理解论文的应用场景，判断不同方法是否可比，替代人工进行方法审计。 

 

## **三、产品形态** 

​                ● **网站形式**：开发一个**类似博客的网站**，**无需自购域名和服务器**，可使用 Cloudflare 免费托管。 

​                ● **界面布局**： 

​                ● **左侧**：列出不同的算法（对应不同论文转化出的 MCP/Agent）； 

​                ● **右侧**：选择数据集； 

​                ● **点击即可获得评测结果**，整体像一个带搜索栏的报告页面。 

​                ● **交互功能**：提供**论文上传入口**，用户可上传新的 GSGP 相关论文，系统自动解析并生成新算法，实时参与计算与对比。 

 

## **四、数据来源与维护** 

​                ● **存量处理**：团队先手动处理已有的 GSGP 相关存量论文（核心文献为 GPT paper-to-agent 相关，GSGP 类资料极少且更新极慢）。 

​                ● **增量支持**：系统支持用户**自行上传**新的相关论文，团队**不负责后续维护**，由用户自行贡献算法。 

​                ● **文献搜索**：实时抓取增量论文由文献搜索 Agent 完成，无大技术障碍。 

 

## **五、主要技术挑战** 

​                ● **MCP 生成不稳定**：paper-to-agent 项目当前仅为概念验证（Proof of Concept），在生物学场景验证过但未产品化。实际运行中 MCP 容易崩溃、调用掉线，各步骤产出不清晰，难以定位崩溃点。 

​                ● **改造需求**：需要对该项目进行**深度改造和优化**，使其能稳定地产出 MCP，并适配 GSGP 领域的论文特点。 

​                ● **范围控制**：为控制工作量，当前仅聚焦于 GSGP、GWAS 等自身相关领域的文章，暂不扩展到其他领域。 

 

##             **六、**     **下一步计划**

​                ● **任务**： 

​                ● **优先试跑**  paper-to-agent 项目，验证其将论文转化为 MCP 的效果； 

​                ● 定位并解决 **MCP 生成不稳定、易崩溃、各步骤产出不清晰**的问题（这是当前最大风险点）； 

​                ● 基于该项目做**改造和优化**，使其能稳定地产出 MCP，并适配 GSGP 领域论文； 

​                ● 若原项目无法直接使用，考虑借助其通用壳（如结合 scale 或 Hawk）做二次开发。 

​                ● **目的**：打通“论文 → MCP → 可调用 Agent”的核心技术链路，这是整个方案落地的关键前提。
